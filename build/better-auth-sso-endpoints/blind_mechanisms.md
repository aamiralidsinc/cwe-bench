# Mechanisms covered and changed

1. Registration with `skipDiscovery: true` (POST /sso/register): caller-supplied `tokenEndpoint`, `userInfoEndpoint`, `jwksEndpoint`, `authorizationEndpoint` and `discoveryEndpoint` were stored with no host check and later fetched at sign-in. Now each must be http(s) and either a trusted origin or a publicly routable host. (Report wording: "configure the addresses the server uses", "however the address is written". Finding the unchecked skipDiscovery branch came from reading the code.)
2. Registration with discovery on (POST /sso/register): explicit endpoints in the body override the discovered ones (`existingConfig ?? discovered`), so they skipped the trusted-origin check that discovered endpoints get. The same gate now runs on them before discovery starts. (Found by reading `discoverOIDCConfig`.)
3. Provider update (POST /sso/update-provider): `oidcConfig` endpoint fields were merged into the stored config with no host check. The same gate now applies. (The report's "every way it can be reached" pointed here; the path itself came from reading the code.)
4. Sign-in callback (`handleOIDCCallback`, used by /sso/callback/:providerId and the shared callback): before the token exchange, the userinfo fetch and the JWKS fetch, the stored `tokenEndpoint`, `userInfoEndpoint` and `jwksEndpoint` are checked again. This covers rows stored before the fix and endpoints carried through `ensureRuntimeDiscovery`. Operator-declared `defaultSSO` providers are exempt. (The report described this "during a sign-in" request. Which fetches happen here came from reading the code.)
5. Host classification: `isPermittedProviderUrl` parses with WHATWG `URL`, the same parser fetch and jose use, then reuses `isPublicRoutableHost` from `@better-auth/core/utils/host`. That function rejects loopback, `localhost` and `*.localhost`, private, link-local and IMDS addresses, CGNAT, unspecified, IPv4-mapped, NAT64, 6to4 and Teredo forms, cloud-metadata names and trailing-dot forms. Because `URL` canonicalises the host first, decimal, hex, octal and short IPv4 spellings are covered. (The report pointed to the requirement "however the address is written" and to loopback, private, link-local and metadata hosts. The existing core helper came from reading the code.)

Not changed (deliberate): discovery still requires a trusted origin for the discovery URL and for discovered endpoints, which is stricter than "trusted or public" and is the current behaviour. The `issuer` field is not gated, because SAML uses it without fetching and runtime discovery already checks the URL derived from it.

Not covered (limits of a syntactic check): public DNS names that resolve to private addresses (DNS rebinding), and HTTP redirects that a permitted IdP returns from the token, userinfo or JWKS endpoints. The token and JWKS fetches live in `@better-auth/core` (`validateAuthorizationCode` and `validateToken`), and I did not change them.
