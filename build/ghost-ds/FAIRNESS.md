# FAIRNESS.md — ghost-ds (pre-trial fairness & leniency review)

Scope of this review: `tasks/ghost-ds/instruction.md`, all of `tasks/ghost-ds/tests/`, `tasks/ghost-ds/solution/fix.patch`, `build/ghost-ds/manifest.json`, `build/ghost-ds/notes.md`, `build/ghost-ds/checks/*.patch`, `tasks/ghost-ds/environment/injection.patch`. No Docker, trials or gates were run; no upstream lookup. Test identity is `file::it-name` (JUnit classname = the `describe` block).

Summary of the task: SVG (and non-image) bytes chosen by name/declared type reach image storage from five image-storage sinks (content-archive images, CSV avatars, remote media inliner, direct upload, bookmark mention-icon cache); SVG must be sanitized, non-qualifying contents must not be stored, legitimate use unchanged. Reference fix: content allowlist from the site's configured upload extensions + shared DOMPurify SVG sanitizer applied at each sink. Gate evidence (manifest): nop 18/18 security fail, 15/15 functional pass; oracle 3×1.0; 8/8 patch checks as declared.

## 2. Leniency — wrong fixes and their catchers

### By security property

- **P1 — contents must be a configured image format (bytes decide).** Most plausible wrong fix: *"is it any real image?"* (sharp decode / `image/*` mime) instead of the configured extension list. **Caught** by security/import-db.test.js::archive import: does not store an unaccepted image format and security/upload-images.test.js::upload: refuses an unaccepted image format (AVIF). A name/mimetype-only allowlist is **caught** by the SVG-behind-raster and text-behind-raster tests, and by checks/fix-misses-upload.patch (declared `security_fail`, gate-verified).
- **P2 — SVG (incl. gzipped) sanitized before store; sanitized SVG kept, not discarded.** Most plausible wrong fix: hand-rolled sanitization that strips only `<script>` elements (the first item of the instruction's removal list). **NOT CAUGHT** — see U1. Second wrong fix: *reject SVGs that contain unsafe content instead of sanitizing them*. **Partially caught**: functional/upload.test.js::upload: accepts a real SVG and stores it sanitized and functional/media-inliner.test.js::remote media: still stores a remote SVG both feed `h.unsafeSvg()` and require it kept; but the archive/avatar levers only ever store clean fixtures → **not caught there** (U2). Refuse-*all*-SVG is **caught** by functional import (checks/fix-overbroad-svg.patch, declared `functional_fail`).
- **P3 — holds at every image-storage sink.** Most plausible wrong fix: patch only the reported archive path (or any single lever). **Caught** per lever by the corresponding security tests; the checks/ patches fix-misses-importer / -inliner / -upload / -avatars / -mention-icon (each = full fix minus that lever) are all declared `security_fail` with functional green (gate-verified). A solver who misses T5 (mention icons) fails 2 security tests; missing T4 fails 2; etc. No lever is free.
- **P4 — non-qualifying file not stored; import/fetch continue; upload refused with a 4xx.** Wrong fix: abort the whole import at the first bad file → **caught** by functional/import-db.test.js::archive import: keeps valid images when one file is unusable. Crash-as-refusal → **caught** on upload (4xx asserted, a 500 fails) and on import (a throw fails the continuation test) — consistent with wrong_fix_catalogue's "n/a" note for imports.
- **P5 — legitimate use unchanged.** Refuse-all-SVG → **caught** (fix-overbroad-svg). Validating media/files as images → **caught** by functional/import-db::imports a non-image download and functional/media-inliner::routes media and file responses.

### Wrong fixes no test catches

- **U1 (high) — shallow SVG sanitization.** Every attack payload embeds the marker inside a single `<script>` element (helpers.js `unsafeSvg`), and the only sanitization-content assertion is `content.includes('<script') === false` (functional/upload.test.js). A fix that strips `<script>`…`</script>` via regex — leaving `onload=`/`onerror=` event handlers, `<foreignObject>` and embedded documents that the instruction explicitly requires removed — scores 1.0.
- **U2 (high) — "discard unsafe SVG" on the import levers.** `security/import-db` and `import-avatars` accept rejection (marker absent); `functional/import-db::still imports SVG and SVGZ images` and `functional/import-csv` use only clean fixtures (`ghost-logo.svg/.svgz`, `me.png`). A fix that sanitizes on upload/inliner but *drops* SVGs containing scripts from archives/avatars violates "A sanitized SVG is stored, not discarded" and still scores 1.0.
- **U3 (medium) — case-sensitive SVG route with discard.** Sanitize only lowercase `.svg`/`.svgz`; anything else (e.g. `.SVG`) falls to the content check and is dropped. The upper-case security test passes (nothing stored), and no functional test imports an upper-case SVG. Violates "upper-case extensions" + "stored, not discarded".
- **U4 (low-medium) — partial upload middleware.** Content-checking `type === 'images'` only, leaving the media-thumbnail path (`mediaValidation`) and the icons upload type unguarded (the reference also covers them). No test drives `mediaValidation`.
- **U5 (low) — rename-on-store of rejected formats.** The AVIF security tests assert only name-absence (`!name.includes('avif-attack')`) rather than no-stored-bytes; a fix that stores the bytes under a fresh name slips past that one assertion (constrained by other tests; exotic).

Catalogue cross-check: `wrong_fix_catalogue` claims hold up — crash-as-refusal is genuinely unscorable on imports and 500s fail the upload 4xx assertion; each named lever-omission has a matching `checks/` patch.

## 3. Hints in instruction.md

No file, function, module, library or flaw count is named. No leak-terms appear. Four sentences nonetheless paraphrase mechanism or enumerate variants:

1. **"Other image entry points already reject or rewrite the same kind of document."** (Observed impact) — paraphrases the fix approach (reject non-images / rewrite-and-store SVGs) and points at the existing model implementation. Neutral: *"Other image entry points are not affected the same way."*
2. **"The bytes decide, not the file name, the declared media type, or an extension taken from a URL."** — the property is fair and necessary, but the tail enumerates the three trap channels (name ≈ T1/T3, declared media type ≈ T2/T3, URL extension ≈ T2). Neutral: *"The file's contents alone decide; no name, label or type declared alongside the file may."*
3. **"This holds for every way a file can reach image storage: content archives of every asset kind, media fetched from a remote address, uploads, and images attached to link previews."** — the four-item list is effectively the lever map (T1+T4, T2, T3, T5). Neutral: keep the lead-in, drop the enumeration — *"This holds for every way a file can reach image storage, not only the example above."* (Scope is already restated in Constraints: "Any path that writes image storage is in scope".)
4. **"SVG contents, including gzip-compressed SVG, must be sanitized…"** — "gzip-compressed SVG" names the `.svgz` variant. Neutral (mild): *"SVG contents, in any packaged form the site accepts, must be sanitized…"*

Checked and **kept** (fairness depends on them): the removal list "no script elements, event-handler attributes, foreignObject or embedded documents remain" — this is the property that makes shallow sanitization wrong (pair with test tightening A below); and the legitimate-use enumeration ("JPEG, PNG, GIF, WebP and ICO… alternate extension spellings and upper-case extensions… contents in a different allowed format than the file name; SVG and SVGZ… media and attachment files… a link preview still receives its icon") — required for the functional tests to be fair. "These are examples, not the full set" is good; no flaw count is given.

## 4. Realism of the traps

- **T1** — real upstream code (`data/importer/handlers/image.js` selects by extension/folders), reachable through the real `ImportManager.loadFile` on a ZIP (`POST /ghost/api/admin/db`) and the CSV asset store (`POST /ghost/api/admin/posts/upload`). Not planted.
- **T2** — real upstream media-inliner (`getMediaStorage(extension)`), reachable via `importUrl` (admin media/inline, CSV remote media). Not planted.
- **T3** — real upstream `web/api/middleware/upload.js` (name + client mimetype allowlist; already sanitizes SVG — consistent with "other entry points already reject or rewrite"). Not planted.
- **T4** — injected (`content-files.ts` avatar handler via the generic `ImporterContentFileHandler` into image storage). Realistic sibling code: a new asset kind reusing the generic handler *with* the image extension/content-type allowlists — exactly the maintainer mistake of trusting metadata checks. Reachable through the real CSV import. Not contrived.
- **T5** — injected (`oembed/mention-icon-cache.js`). Reachable through `OEmbedService.buildBookmarkData` on the admin oembed route. Most planted-feeling of the five: the neighbouring bookmark-image path already content-checks at this commit (per notes.md), so the new helper skips an existing lesson, and its docstring observes "the response may be any type the publisher chooses" while storing blindly. Still plausible as rushed feature code next to existing link-preview handling. One test-side coupling to flag: functional/mention-icon hardcodes the injected layout `/content/images/icon/`.

## 5. Verdict

**NOT READY.** The oracle and independent alternative fix show correct fixes pass, and no test asserts an unstated requirement — the failures are on the leniency side (an instruction-violating fix can score 1.0) and on hint leakage in the instruction. Required changes before trial:

1. **Instruction (remove fix-approach and lever-map hints):** replace sentence 1 of §3 with *"Other image entry points are not affected the same way."*; replace the tail of sentence 2 with *"The file's contents alone decide; no name, label or type declared alongside the file may."*; replace the enumeration in sentence 3 with *"not only the example above."* (sentence 4 optional).
2. **Tests (close U1):** extend `helpers.js` payloads (or add a second payload) so an unsafe SVG also carries an event-handler attribute and a `<foreignObject>`/embedded document with the marker; assert their absence after storage in functional/upload.test.js::accepts a real SVG and in one import lever (functional/import-db SVG case is the natural home).
3. **Tests (close U2, U3):** in functional/import-db.test.js::still imports SVG and SVGZ images, build the archive from `h.unsafeSvg()`/`h.unsafeSvgz()` (add an upper-case `VECTOR.SVG` entry) and assert the stored files contain `<svg` and not the marker; mirror one unsafe-avatar-SVG case in functional/import-csv.test.js.
4. **Do not loosen** the basename/case/mismatch-name assertions, the byte-identity `deepEqual`s, the `/content/images/icon/` prefix or the upload temp-file assertion — they are behavior the instruction pins ("exactly as today") and are recorded as medium-risk false-negative candidates only.
5. After edits, the builder must re-run the gate (nop, oracle, the 8 `checks/` patch expectations) — the recorded runs predate any change and cannot be relied on.
