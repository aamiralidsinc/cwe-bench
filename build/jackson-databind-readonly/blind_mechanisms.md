# Mechanisms covered by blind.patch

Changed:

1. Merge path: a getter-only READ_ONLY property got a SetterlessProperty whenever merging applied (setDefaultMergeable, @JsonMerge, configOverride(...).setMergeable). The getter value was then mutated in place. This happened for new objects (readValue, convertValue, treeToValue) and for updates (readerForUpdating, updateValue), for POJO, Map, Collection, AtomicReference and ObjectNode values, and also through @JsonUnwrapped, Shape.ARRAY, polymorphic subtypes, mixins and interface/superclass annotations. It includes the quirk where an RO property with an explicit name still bound under its implicit name. Fix: once naming is final, POJOPropertiesCollector drops READ_ONLY properties entirely when they keep no writable accessor (getters too) and registers their final names as ignorable. -- POINTED TO BY THE REPORT (the example and "merge nested objects", setDefaultMergeable).
2. USE_GETTERS_AS_SETTERS path for Collection/Map READ_ONLY getters: the factory's guard was name-based (builder.hasIgnorable), and RO names are not added as ignorable when the class has an @JsonAnySetter. So an RO list or map was appended to even on new objects, without any merging. Fixed by the same removal in (1). -- FOUND BY READING THE CODE (the report only says "other types ... other ways").
3. Creator path: a creator parameter belonging to a READ_ONLY property was populated from input when the class has an any-setter, because CreatorProperty.markAsIgnorable only ran for names in the ignorable set. Fix: the collector records RO external names (BeanDescription.getReadOnlyPropertyNames()), and BeanDeserializerFactory.addBeanProps marks matching creator properties ignorable when an any-setter exists. Such input then goes to the any-setter, as other RO input already does. -- FOUND BY READING THE CODE ("however the object is built" is generic).
4. @JsonAlias on a READ_ONLY property: with merging, input under the alias reached the setterless property. Aliases are now collected before mutators are dropped and registered as ignorable, unless a writable property uses that name, so alias input is ignored without an error. -- FOUND BY READING THE CODE.

Not changed (verified already safe, or deliberately left):
- @JsonIgnoreProperties(value=..., allowGetters=true): at class level, via configOverride, and at property level (contextual). Already blocked in merge, getters-as-setters, creator and any-setter cases. -- pointed to by the report; probes confirm no change needed.
- Input whose key names an RO property still goes to an @JsonAnySetter when one exists. This is unchanged and intentional upstream ([databind#1805] comment).
- Not handled: case-insensitive matching (ACCEPT_CASE_INSENSITIVE_PROPERTIES) of RO names, an RO @JsonUnwrapped property, and Shape.ARRAY with an RO element. The value now stays unchanged, but the input raises UnrecognizedPropertyException or MismatchedInputException. Before the patch the merge case was silently mutated, and the non-merge case already raised the same exception.
