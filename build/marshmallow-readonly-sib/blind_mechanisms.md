# Mechanisms covered and changed

1. `Schema.__init__` merged the constructor's `load_only`/`dump_only` with `class Meta` options using `or`, so any constructor argument (including the dotted names an enclosing schema passes down to a nested schema it builds from a class or class name) replaced the Meta declarations instead of adding to them. Changed to a set union. Report pointed to it: yes (the example, the line "Declarations add up", and the list "in class Meta ... as arguments when a schema is created ... from an enclosing schema"). The exact `or` line I found by reading the code.
2. `fields.Nested.schema`, path for a schema *instance* (including callables/lambdas that return an instance, `Pluck` over an instance, and `Nested` inside `List`/`Tuple`/`Dict`): dotted `load_only`/`dump_only` names from the enclosing schema were silently ignored (only `only`/`exclude`/`many` were applied to the copy). It now adds them to the copy's own declarations. Report pointed to it: partly ("from an enclosing schema with dotted names ... at any depth, whichever way the input reaches it"); that the instance path was a separate, unhandled path I found by reading the code.
3. Isolation for (2): the instance path used `copy.copy`, so the copy shares field objects (and their cached nested schemas and `root`) with the original instance. Applying the new declarations to shared fields would have leaked them into the original instance and other parents, and deeper dotted names would have resolved against the original's root. Added `_unbound_field_copy` (recursively copies contained fields such as `List.inner`, `Tuple.tuple_fields`, `Mapping` key/value fields, and clears the binding and cached nested schema) and used it for the copy's `declared_fields` when declarations are added. Report pointed to it: the requirement "The schema it encloses keeps behaving exactly as its own declarations say wherever else it is used"; the shared-field mechanism I found by reading the code.

Not changed (deliberately): `unknown=INCLUDE` still passes through input keys of read-only fields as raw values, because the report requires such input to be handled exactly as the library already handles it for an ordinary read-only field.
