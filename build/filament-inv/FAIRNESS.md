### Contracts kept on purpose (minimum wording)

- Refusal form: client error or validation error, not a server error, no side effect. Needed by both upload tests and both reauth tests (crash refusals fail them).
- Name of the new form field: `password`. Needed by the legitimate turn-off test and the wrong-password test. Kept as a field name, without saying where the form lives in code.
- "any code generated before it": needed because RFC 6238 only requires rejecting a second use of the same code; rejecting older codes after a newer one is stricter, so it is stated.
- "exactly as it does to a wrong password": fixes the observable answer (generic error, no challenge) for denied accounts.
- "works exactly as today" for uploads: needed so that a fix that blocks all anonymous uploads is visibly wrong (the legitimate upload test runs with no one signed in).
