## 1. What the project is

CWE-bench builds security-fix tasks for evaluating coding agents. Each task is a real open-source
repository pinned at a vulnerable commit, plus:

- an `instruction.md` that states the goal (the security property and what must keep working),
  without fix hints;
- hidden security and functional tests;
- a reference fix and a set of check patches that prove the tests are sound.

A task is a **breaker** when **both** solver models fail all 3 graded runs:

- **DeepSeek V4.1 Flash** (`deepseek-flash`);
- **MiMo-V2.6-Pro** (`mimo-v2.6-pro`).

Each run is a Claude Code agent, offline, with a 3-hour limit. A 3 h timeout counts as a fail. Only
breakers are delivered to the client.

- **Our repo:** `github.com/aamiralidsinc/cwe-bench` (this repo).
- **Client repo:** `github.com/marahassan8/cwe-bench`, which holds the delivered tasks.
  - main = `49a4023`: 55 tasks, 18 withdrawn.

## 3. History in short: sibling injection, then stacking

**Sibling injection (the `-ds`, `-s2`, `-s3` tasks).**

- **How it builds a task:** a DeepSeek builder agent takes one real advisory and **injects extra
  vulnerable sites ("siblings")** next to it, then writes tests for all of them.
- **What happened:** batches 3–6 were almost all sibling tasks. Their yield fell:

  | Batch | Both-model fail rate |
  |---|---|
  | b1 | 37% (28% confirmed) |
  | b2, b3 | 17% |
  | b4 | 11% |
  | b5, b6 (snapshot) | about 2% |

- **Why it fell:** two audits investigated, `reports/yield-audit-20261029/INDEPENDENT.md` and
  `PATTERN-COMPARISON.md`. Findings:
  - **Recipe mix explains most of it.** Stacking gives about 31% both-fail; siblings about 12–15%.
    The early batches were stacking.
  - **Siblings are found quickly.** In 190 of 250 sibling tasks, DeepSeek's first run opened every
    trap file within minutes. In 85% of b5–b6 tasks the injected siblings copy the advisory's own
    code idiom, so one grep finds them all. In 91% the instruction describes the traps (the listing
    check fails). Often one shared fix covers every site.
  - **These patterns come from our own builder prompt** (`common/builder/TASK-BUILD-PROMPT-v1.md`),
    not from the diversity experiment.
  - **The b5–b6 2% was mostly a snapshot effect.** Failing tasks finish last. Expected final yield:
    about 6–10%.
  - **The builder model is not the cause.** Siblings were DeepSeek-built throughout; the few Opus
    builds did worse.

**Stacking (the `stk-` tasks).**

- **How it builds a task:** it uses no planted bugs. It stacks several **real** upstream bugs in
  one repo, picked by history pattern:
  - **H3:** a fix that left or created a follow-up bug.
  - **H4:** a fix that covered only one of several routes.
- **Yield:** H3 36% and H4 32% both-fail in b1–b2.
- **Why we switched back:** stacking had stopped only because its pool ran out.
- **Guide:** `pipelines/stacking/GUIDE.md`. Design background: `docs/STACKING-EXPLORATION.md`.
