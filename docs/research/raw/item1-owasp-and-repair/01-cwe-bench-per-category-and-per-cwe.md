### 4. Qualitative failure analysis (quotes)

**The paper has no per-category or per-CWE failure analysis.** It only says ([P-tex] results.tex §subgroups and discussion.tex):
- "Across OWASP categories, Integrity failures (A08) are the hardest"
- "Performance varies far more across vulnerability categories than across languages, and the leading agent changes from one category to the next."

**[S-html], the v1 heatmap subtitle:** "By weakness type: models share weaknesses in data integrity (A08), insecure design (A06), and authentication (A07)". The v0 subtitle was "…such as authentication (A07), error handling (A10), and data integrity (A08)". The language subtitle is "By language: JS/TS and C/C++ lead, Java and Rust trail".

**[S-html], "In practice: where agents fail":** four stages, not tied to categories.
- Localization failure: "The agent never reaches the vulnerable code."
- Missed detection: "The agent inspects the vulnerable code but judges it benign."
- Wrong invariant: "The agent patches the right code without restoring the security property."
- Incomplete remediation: "The agent fixes some vulnerabilities but leaves others open."

The site's sample task is blurhash-rs, CVE-2023-42447, an A10-style panic. It says: "A repeated one-path fix indicates that the model stops at the first plausible cause."

**[B1]:** "Ten tasks are solved by none of the top three, and nine are solved by none of the three. One of the ten is solved only by DeepSeek V4.1 Flash and Hy4 Preview. The unsolved nine span six languages, and three of them are Software or Data Integrity Failures (OWASP A08)." The wording about the nine is garbled in the original. Here "top three" means Grok 4.7, GPT-6 Astra and Claude Opus 5.5.

**[B0] "Where agents fail" (v0):** "They fail later, when the fix isn't where the bug is or doesn't have an obvious shape. Four patterns account for most of it."
- "Incomplete fixes. … an access token can be canceled in three places … closing two of the three still scores zero."
- "Trusting a defense that does not work. … compares it against a short fingerprint … the fingerprint is fetched from the same server as the file."
- "Over-correction. … an agent blocks an entire category of input."
- "Reasoning that stops one step early. … A token created with the 'never expires' option has no expiry date, so its entry is dropped as soon as it's added … The fix should've occurred where tokens are created, not where they are canceled."

The blog does not tag these examples with categories. My inference only: the token examples look like A07 (CWE-613) and the fingerprint example like A08 (CWE-494 or CWE-345).
